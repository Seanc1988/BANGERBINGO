# v1.12.0 Beta — Spotify Live Reliability + Clip Mode

## Implemented

- Persistent Windows Spotify media-session watcher replaces repeated PowerShell status launches as the primary metadata path.
- Watcher samples the existing Windows media session every 250ms, emits track/playback changes immediately, and emits a 1-second heartbeat.
- Legacy PowerShell status check remains as a 5-second fallback only if the persistent watcher is silent.
- Watcher process automatically restarts if it exits.
- Optional connected-account playback-state metadata acts as a secondary fallback when the Windows watcher is stale.
- Music Bingo Clip Mode:
  - 30 seconds by default
  - configurable 10–90 seconds
  - optional automatic Next
  - configurable 0–3 second transition
- Host UI now shows a live `NEXT SONG IN XX SEC` progress bar.
- Manual Next uses the same transition while Clip Mode is enabled.
- Desktop-only transition performs a best-effort Windows playback-output fade, advances Spotify, then restores the prior volume.
- If audio-output fading is unavailable, Spotify still advances normally.

## Field-test priorities

1. Confirm typical track-title latency is consistently in the 1–3 second range.
2. Test 30-second automatic advance over a full Music Bingo round.
3. Verify fade down / advance / fade up on the actual event laptop and audio interface.
4. Confirm pausing Spotify cancels the clip timer and resuming restarts correctly.
5. Confirm pregame/background music still stays out of Played Songs when Live-only tracking is enabled.

## Platform note

The Windows watcher is the primary integration and does not require Spotify Web API playback metadata. The connected-account fallback is optional. Spotify's current developer policies should be reviewed before commercial distribution of any account-connected player-control functionality.
